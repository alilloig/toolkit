How to read this

  • Installed and enabled are different facts in different files. A plugin can sit on disk and be switched off — those show as installed but disabled.
  • Invocation counts are not comparable across plugin types. A hook or LSP plugin fires on every tool call; a slash command only fires when you type it. Treat the numbers as "does this get used at all", not as a ranking.
  • A usage count on a plugin that is not installed means it was installed at some point and later removed.
  • Component counts are read from disk. An entry that is only a git pin has nothing on disk until it is installed, so its counts show as — — unknown, not zero.
  • Always-on cost comes from claude plugin details where the CLI was available — a real tokenizer estimate of what each plugin adds to every session. It only resolves for installed plugins; the rest of the catalog has no cost figure. When the CLI is unavailable the dashboard falls back to an offline proxy (summed skill-description length), which undercounts agents relative to skills.
  • Agents cost far more than skills. The heaviest always-on line item here is usually an agent-bearing plugin, not a skill-heavy one. Any ranking that weights skills over agents is wrong — that is why this dashboard ranks on tokens, not on skill count.
  • A 0 in the token column means "adds nothing to the prompt", not "does nothing". Hook-only and LSP plugins run harness-side: they can fire thousands of times while costing zero context. Do not read a 0 as dead weight.
  • Component counts come from the disk walk, not from the CLI. The two count different things: the CLI folds slash commands into its "Skills" bucket, counts hook events rather than handlers, and reports 0 for MCP servers and agents declared in plugin.json rather than as files. Both inventories are shown in the detail sheet rather than blended into a number that is true of neither.
  • MCP tool counts are not included. Only a running server knows how many tools it registers, and that varies with version and auth state.
